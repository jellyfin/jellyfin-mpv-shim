# i18n: extraction and seeding

`CLAUDE.md` carries the workflow and the one rule with real blast radius (never
`--merge`, never hand-edit a `.po`). This is the reasoning behind the tooling
choices.

## 1. Extraction is `xgettext`, not `pygettext3`

Three reasons, and the first is disqualifying on its own:

- `pygettext3` **cannot extract `msgctxt` at all** — zero contexts from a file full of
  `pgettext` calls;
- it offers GNU-vs-Solaris location *style* rather than location *granularity*;
- it marks no format strings.

## 2. References are `--add-location=file`, not line

A line number meant that every string added above another rewrote all of them, which
was **87% of a 17k-line sweep**. Adding one string mid-file now costs ~430 lines
across the 86 locales instead of ~17,000.

## 3. `regen_pot.sh` uses `find`, not a glob

It `find`s every `.py` under `jellyfin_mpv_shim/` rather than globbing. It used to use
`**`, which without `shopt -s globstar` expands like `*` — so nested packages
(`mpvtk_browser/pages`, `/settings`, `/components`, `/gateway`) were never scanned and
**~150 strings silently could not be translated**.

## 4. Why `--merge` is a maintainer operation, not part of a feature branch

The `.pot` is the template Weblate reads to discover new strings; filling the 86 `.po`
files in is Weblate's job.

Merging locally rewrites every locale — msgmerge rewrites line references and re-wraps
whatever it touches — which is ~10k lines across 86 files **even when no translation
changed**. Weblate lands real translations on `master` continuously, so that churn
collides with `master` in files nobody on the branch edited, and the conflicts are
unreadable because the diff is almost entirely reference comments.

`--merge` has to be committed and merged within the hour to be worth anything.

There is a `weblate` remote pointing at Weblate's git export; `MASTER_REF=weblate/master`
merges against the freshest volunteer work rather than whatever `origin/master` last
took.

## 5. Seeding from jellyfin-web

`./seed_from_jellyfin_web.py --web-src <checkout>` fills *untranslated* entries from
jellyfin-web's translations. This is legitimate — jellyfin-web is GPL-2.0-or-later and
this project is GPL-3.0 — and worth ~6,900 entries, because a quarter of our strings
are word-for-word theirs.

**What it writes ships.** The guards are the ones review would apply — identical
English, the same client UI, jellyfin-web's own translators agreeing on the wording in
that language, placeholders intact — so holding the result back buys a second opinion
about our screen and costs the string, in every language, until somebody gives one.
Nobody was giving one: the flag-everything era left ~6,900 entries fuzzy and shipping
nothing. `--fuzzy` restores it if a particular sweep warrants it.

A re-run also **promotes** what earlier runs left fuzzy, but only where it re-derives
the identical value from the key the entry records — so an entry a volunteer edited and
left fuzzy is left exactly as they left it, and one jellyfin-web has since reworded is
reported as `diverged` rather than quietly updated.

**A sweep can move the note off the string it described.** When a source string is
reworded, msgmerge attaches its old translation to the new msgid, marks it fuzzy, and
carries the translator comments across — our `# seeded from jellyfin-web:` line
included. The note then credits a key whose English we no longer use, and promotion
would re-derive that key's value, find it unchanged and clear the flag: `Blend Frames`
shipping the translation of `Dropped frames`, `Reasons` that of `Seasons`. So the key's
English has to still equal our msgid before the note is trusted at all
(`marker_is_current`); a note that fails that is not ours, and the entry goes back to
being an ordinary fuzzy entry nobody may touch. The August 2026 sweep reported 2,428 of
them, half of which it had just created.

Each seed carries a `# seeded from jellyfin-web: <Key>` translator comment, which is
both the provenance and the **only durable place for the mapping**: the `.pot` is
regenerated wholesale by xgettext, so a label written there dies on the next
`regen_pot.sh`. It is also what makes promotion possible at all — it is the one thing
distinguishing our seed from a volunteer's work.

**Placeholders are compared in jellyfin-web's notation.** gettext keys on the English
exactly, so our `"%d episodes"` did not match their `"{0} episodes"` and strings we had
taken from them word for word could not be seeded in any language. Matching converts
ours to `{0}` form and seeding converts their translation back, giving each `{i}` the
conversion our own msgid spends on that argument. A translation that **reorders**
positional arguments is skipped: `%s` is filled from a tuple in occurrence order, so a
swap would format cleanly, read perfectly, and name the wrong thing. Named conversions
(`%(from)d`) carry their own identity and may move freely. See
`tests/test_seed_from_web.py`.

**Seed last, and merge before sweeping again.** `--merge` treats master's `.po` as the
definition and ours as a compendium, so an entry master holds as fuzzy-with-a-value
wins and the seed is silently reverted.

## 6. `_p(context, string)` — one word, two meanings

gettext keys on the English, so a string reused in two senses collapses to one entry
and no language can tell them apart.

A context is **part of the key**, so adding one to a string that did not need it
discards every existing translation of it. Only do it where the senses genuinely
differ.

The known cases in this codebase, each confirmed against jellyfin-web needing separate
keys for the same pair:

| string | the two senses |
|---|---|
| `Record` | picker label vs button verb |
| `Channels` | picker label vs Live TV tab |
| `Download` | button verb vs dialog heading |
| `None` | no track vs no home section — a gender-agreement problem in Italian |
